# 插件契约检查清单与反模式

## 契约字段逐一检查

### kind（唯一 id）
- [ ] 全局唯一、稳定字符串（不改名——改名等于删除旧插件）
- [ ] 用于注册表分发（`registry.get(kind)`），不用于逻辑判断（核心禁止 `if kind === ...`）

### keyPrefix / 路由键
- [ ] 实体 id 格式 `<prefix>:<插件内稳定键>`，注册表按前缀路由到插件
- [ ] prefix 一旦持久化就是路由键——改 prefix 需迁移已存数据

### connect（一次性握手）
- [ ] 输入是用户可提供的 plain config（可 JSON 序列化）
- [ ] 校验 + 握手 + 发现，全部经注入 port，不直接碰平台
- [ ] 失败抛结构化错误（用户可读信息 + 机器码），核心原样透传给 UI
- [ ] 返回的 Connection.id 由**内容哈希派生**（`kind:<hash(normalizedConfig)>`）——去重靠构造

### create（每次启动重建）
- [ ] 只从持久化 state 重建实例，**不重新握手/登录**
- [ ] 同步返回或惰性初始化均可，但不得在核心 hydrate 路径上抛同步异常（catch 后跳过该源）

### state（opaque 持久化）
- [ ] 可 JSON 序列化（凭证等敏感字段由调用方存储层负责加密）
- [ ] 核心不解释内容——插件升级改 state 结构不需要核心配合

## 反模式速查

| 反模式 | 症状 | 纠正 |
|---|---|---|
| 核心按 kind 分支 | `if (kind === 'a') specialCase()` | 通用化进契约可选方法或插件内 |
| connect 里做持久化 | 插件自己写存储 | 核心统一持久化 Connection，插件只返回 |
| create 里重新登录 | 每次启动要求凭证/慢 | session 放 state，connect 一次性 |
| 随机实例 id | 重复添加出现重复实例 | 内容哈希派生 |
| 契约引用 UI 类型 | 插件接口 import 组件库 | 契约层数据模型零 UI 依赖 |
| 插件间互相 import | 耦合、循环 | 共享逻辑下沉核心或独立 util 包 |
