# 新建移动端项目

从零开始一个 aukcraft 家族的移动 app。核心思路与桌面端一致：从中性色核心直接生长，第一天就按规则实现。

## 流程

### 1. 落地 token + 声明产品 accent

用生成脚本产出主题原料；非 CSS 栈（React Native / Flutter / SwiftUI）用 `json` 格式转成各平台的主题对象：

```bash
python scripts/generate_theme.py --accent "<产品accent>" --format json
# WebView 类栈（Tauri Mobile）可用 css / shadcn / tailwind 格式
```

一个 app 只声明一个 accent，与产品站点对齐；拿不准时用组织级 Auk Teal `#14B8A6`。

### 2. 按工具形态选导航结构

遵循平台惯习，而非网站惯习——绝不把网站的顶部编辑式导航搬进 app：

| 产品形态 | 导航结构 |
|---|---|
| 多目的地工具 | 底部 tab 栏（≤ 5 个目的地） |
| 线性任务流 | 原生栈导航 + 平台返回手势 |
| 单一主功能 | 单屏 + 底部操作栏 + 必要时上滑设置弹层 |

aukcraft 移动端最可能的形态是**设置类工具**，其主导布局是分组列表：`raised` 分组块、1px 发丝线分隔（向内缩进到文字边缘）、每组上方一个 micro 标签。这与桌面端的面板语法在触摸密度下互为镜像。

### 3. 结构规则

- 窗口背景 `base`；分组/卡片 `raised` + 发丝线；上滑弹层 `raised` + 顶部发丝线，压在 60–70% 黑色遮罩上，滑动可关闭
- **底部操作栏**是家族范式：`raised` 表面、顶部发丝线、一个 accent 文字主操作，背景延伸进底部安全区
- 四边遵守安全区 inset；内容绝不落在刘海、home 指示条或手势条之下
- 每个屏幕只有**一个** accent 主操作，通常在拇指区

### 4. 平台事项

- OS 有强模式的地方——权限弹窗、日期时间选择器、分享面板、上下文菜单、动态字体缩放——原样使用原生组件，一点不改
- 动态字体缩放（Dynamic Type / 系统字体大小）下布局不能破：列表行高随文字伸缩，不写死整体高度
- i18n 运行时切换；关键技术术语（crate、CI、PR、TDD）保持英文

## 新建情形检查清单

在 SKILL.md 共用清单之外额外确认：

- [ ] token 由生成脚本产出或与其逐值一致，无手写近似色
- [ ] 只声明了一个产品 accent，且与产品站点对齐
- [ ] 导航结构单一且符合平台惯习（无网站式顶栏）
- [ ] 动态字体缩放下所有屏幕实测不破版
- [ ] reduced-motion 降级、安全区、拇指区从第一版就位
