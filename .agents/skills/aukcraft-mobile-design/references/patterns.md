# 移动端模式库

移动端特有的交互与视觉模式细节。共享核心（token、accent 配给、零阴影、暗色）见 SKILL.md。

## 触摸反馈：Flight Line 的移动端变形

hover 不存在，桌面端的悬停描边没有附着点：

- **按压反馈**取代 hover：touch-down 时元素的发丝线边框**立即**变为 accent（不播描边动画——手指盖在元素上，700ms 的描边在指尖下播放，读起来是卡顿），外加 `opacity` 0.9 或 scale 0.98。松手后 150ms 回落。
- **常驻 accent 环**标记当前*聚焦/编辑中*的输入框（键盘为它升起的那一个）——这是桌面端常亮 Flight Line 环在移动端的对应物。
- **选中态**（当前 tab、已选项）使用 1px accent 边缘或小 accent 勾，**常驻显示**——因为没有光标可以重新发现状态，选中态必须随时可见。
- 不可交互元素对触摸零响应，与桌面端一致。

## 触控几何

- 最小触控目标 **44×44pt（iOS）/ 48×48dp（Android）**，相邻目标间距 ≥ 8px。视觉可以小于目标（44px 热区里放 24px 图标是正确做法）。
- 主操作放在**拇指区**（屏幕下半部）。参考 `references/new-project.md` 的底部操作栏范式。
- 单手可达优先于对称：屏幕上半部纯展示（标题、状态）、所有操作放在下三分之二，完全没问题。

## 密度与字号

- 比桌面松、比网站紧：列表行高 48–56px，分组内边距 16px，全程 8px 网格。
- 正文 16px（避免 iOS 输入框聚焦时的自动缩放），次要文字 14–15px，micro 标签 11–12px，屏内标题上限 20px semibold。

## 动效与电量

- 过渡 ≤ 300ms、`ease-lock`、只动 `opacity`/`transform`。页面 push / 弹层滑入与平台标准曲线冲突时，服从平台——导航上平台一致性高于品牌缓动。
- **没有 rAF 循环、没有待机动画、没有视差。** 移动端每一个运行中的动画都是用户没点头的电量与发热成本。
- `prefers-reduced-motion`（及 iOS/Android 的"减弱动态效果"）：状态直接切换；导航滑动由 OS 自行减弱。
- 触感反馈：可选、轻微（选中滴答、成功确认）。绝不每次点击都震；绝不做装饰。

## 弹层与对话框

- 上滑弹层：`raised` 表面 + 顶部发丝线；`base` 上压 60–70% 黑色遮罩；滑动关闭必须可用
- 破坏性操作永远不是 accent 主操作，且在弹层中与主操作保持明显的视觉距离
- 全屏对话框仅用于真正的模态任务（授权、首次配置）；其余一律弹层
